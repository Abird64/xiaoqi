# 集成指南

> 目标：让手机上的「小栖步数」把今日步数送进小栖电脑端，并在房间的步数卡 / 挂历上看到。
> 先走「方式 A」验证手机→网页链路，再走「方式 B」接真实后端，排错会容易很多。

---

## 0. 前置条件

| 项 | 要求 |
|---|---|
| 手机 | Android 8.0+（API 26+），有计步传感器（绝大多数手机都有） |
| 电脑 | Windows，运行小栖后端；与手机在**同一 Wi-Fi / 同一局域网** |
| APK | `release/xiaoqi-steps-1.0.0.apk` |
| 网络 | 电脑防火墙放行后端端口（默认 8000；联调面板 8765） |
| Python（仅联调面板） | 3.10+，只用标准库 |

> 手机和电脑不要一个连 Wi-Fi、一个连热点；也不要开“AP 隔离/访客网络”。
> 公司/校园网常隔离终端，建议用手机热点或家里的路由器。

---

## 方式 A：零依赖联调（建议先做）

不需要摄像头、不需要姿态模型依赖、不需要前端构建，只用 Python 标准库。

### A1. 启动联调后端

```powershell
# 在仓库根目录执行
cd android
python tools\dev_server.py --port 8765 --token xiaoqi-demo
```

看到：

```
小栖步数 · 联调后端已启动
  面板    http://127.0.0.1:8765/
  局域网  http://<本机 IP>:8765/
  令牌    xiaoqi-demo
```

浏览器打开 `http://127.0.0.1:8765/`，先确认面板本身能打开。

### A2. 查电脑局域网 IP

```powershell
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike "127.*" -and $_.IPAddress -notlike "169.254.*" } |
  Select-Object IPAddress, InterfaceAlias
```

例如得到 `192.168.1.5`，则手机端地址是 `http://192.168.1.5:8765`。

### A3. 安装 APK

```powershell
adb install -r release\xiaoqi-steps-1.0.0.apk
```

没有 adb 在 PATH 里就用：

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" install -r <apk路径>
```

也可以把 APK 传到手机，用文件管理器安装（需允许“安装未知来源应用”）。

### A4. 手机 App 配置

打开「小栖步数」：

1. 首页横幅提示「还差一步：允许身体活动」→ 点「授予权限」，允许**身体活动**；
2. 点「设置」；
3. 电脑地址：`http://192.168.1.5:8765`（换成你的 IP/端口）；
4. 配对令牌：`xiaoqi-demo`；
5. 点「测试连接」→ 应显示「已连接 · 小栖后端 1.0.0-demo」；
6. 点「保存并启动」；
7. 如果系统提示电池优化，选择允许/忽略；国产 ROM 再到系统设置里允许「自启动 / 后台运行」。

### A5. 验证

- 手机 App 首页出现「计步中」，走几十步后数字增加；
- 点「立即同步」，联调面板 3 秒内刷新步数；
- 面板显示来源 `android-app`、设备 `android-xxxx`；
- 之后默认每 5 分钟自动同步；步数增加 300 以上会提前同步（≥75 秒）。

## 方式 B：接真实小栖后端

### B1. 启动后端

按小栖原项目 README 的方式启动（需要其 `backend/requirements.txt` 完整安装）：

```powershell
cd ..\backend
.\.venv\Scripts\python.exe -m xiaoqi
# 或需要模拟链路时：
# .\.venv\Scripts\python.exe -m xiaoqi --sim
```

> 如果 `backend/requirements.txt` 的依赖没装全，启动时可能因缺少姿态模型/依赖失败；
> 这属于后端环境问题，不影响手机接入链路。可先跑通方式 A 的 `dev_server.py`。

后端启动后会打印：

```
配对令牌  <token>
手机上报  POST /api/ingest/health
前端/WS   ws://0.0.0.0:8000/ws
```

### B2. 取地址与令牌

- 地址：`http://<电脑局域网 IP>:8000`
- 令牌：
  - 看后端控制台；或
  - 浏览器打开 `http://127.0.0.1:8000/api/token`；或
  - App 设置页点「自动获取令牌」（该接口在参考后端目前不鉴权，属已知缺口，仅局域网演示可用）。

> `backend/config.yaml` 里 `phone.token` 默认为空 → 后端每次启动随机生成。
> 想固定令牌，请在你自己的后端配置里设置一个值（参考项目的配置改动，不在本工作区执行）。

### B3. 防火墙放行 8000

```powershell
# 管理员 PowerShell
New-NetFirewallRule -DisplayName "Xiaoqi 8000" -Direction Inbound `
  -Protocol TCP -LocalPort 8000 -Action Allow
```

### B4. 手机 App 配置

同 A4，只是端口改成 `8000`，令牌换成真实令牌。

### B5. 验证整条链

在电脑上：

```powershell
Invoke-RestMethod -Headers @{"X-Xiaoqi-Token"="<令牌>"} http://127.0.0.1:8000/api/state
```

应看到：

```json
{
  "phone": { "steps": 3210, "updated_ts": 1789526000000, "stale": false }
}
```

- 电脑打开小栖房间前端（开发模式 `http://localhost:5173` 或后端托管的 8000）；
- 房间左下步数卡 / 挂历应显示步数；
- 15 分钟没有新上报，前端会显示「待同步」；
- 历史数据：

```powershell
Invoke-RestMethod -Headers @{"X-Xiaoqi-Token"="<令牌>"} `
  "http://127.0.0.1:8000/api/history?from=1788912000000&to=1789516800000"
```

### B6. 用深链快速配对（可选）

把下面 URI 里的地址/令牌换成你的，在手机浏览器打开，或：

```powershell
adb shell am start -a android.intent.action.VIEW `
  -d "xiaoqi://pair?base=http%3A%2F%2F192.168.1.5%3A8000&token=<令牌>"
```

App 会导入并提示「已导入小栖配对信息」。深链只负责写配置，仍需要在 App 里授予权限/启动服务。

## 3. 安装与卸载

安装：

```powershell
adb install -r release\xiaoqi-steps-1.0.0.apk
```

覆盖安装会保留配置与今日步数；卸载会清空：

```powershell
adb uninstall com.xiaoqi.steps
```

停止后台计步：App → 设置 → 停止后台计步。停服务不会清除已记录步数/配置。

## 4. 排障表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 首页一直「待配置」 | 地址/令牌为空，或地址非法 | 填 `http://IP:端口`；点测试连接；地址不要带 `/api/ingest/health` 路径（带了也会自动去掉） |
| 「连不上电脑 / 超时」 | 不同 Wi-Fi、IP 错、端口错、防火墙、AP 隔离 | `ping <IP>`；`Test-NetConnection <IP> -Port 8000`；放行防火墙；关访客网络 |
| 「令牌错误（HTTP 401）」 | 令牌与后端不一致；后端重启后随机令牌变了 | 从控制台/`/api/token` 重新取；固定后端 `phone.token` |
| 「字段不合法（HTTP 400）」 | 极少见；`steps` 非整数 | 本 App 只发整数；若出现请抓包/看后端日志 |
| 「已同步（服务端 60 秒内去重）」 | 60 秒内重复上报，被幂等丢弃 | 正常；等 60 秒或改间隔为 5 分钟 |
| 手机数字在涨，电脑不动 | 自动同步关、服务未启动、地址/令牌错、被厂商杀后台 | 看首页「后台服务」「同步结果」；点立即同步；加电池白名单 |
| 电脑显示「待同步」 | 超过 15 分钟没上报 | 打开 App/点立即同步；检查后台服务是否被清理 |
| 前端显示「无数据」 | 后端重启后还没有手机上报 | 手机点一次立即同步；确认 `/api/state` 有 phone.steps |
| 通知不见了 | Android 13+ 通知权限被拒，或厂商隐藏 | 设置 → 通知权限；前台服务仍会计步 |
| 锁屏后不涨步 | 厂商冻结后台 / 电池优化 | 允许自启动、后台运行、忽略电池优化；重新打开 App 恢复服务 |
| 步数比系统健康 App 少 | 首次安装从 0 起算；跨天断流被丢弃；防跳变过滤 | 属于设计取舍，见设计文档 §3.4；不要以系统健康 App 的“今日”直接对比 |
| 午夜后仍是昨天的数字 | 传感器没有新事件，UI 尚未刷新 | 打开 App 会刷新；服务在跑时零点后的第一个事件会归零 |
| Android 14 启动前台服务报错 | 缺 `FOREGROUND_SERVICE_HEALTH` / 类型不匹配 | 本 APK 已声明；确认安装的是本 APK，不是旧版本 |
| 手机能上网但连不上电脑 | 电脑防火墙只放行专用网络 / 手机在访客网络 | 防火墙对专用+公用都放行；换手机热点测试 |

快速自查命令：

```powershell
# 后端是否活着（不需要令牌）
Invoke-RestMethod http://127.0.0.1:8000/api/health

# 端口是否通（在另一台机器/手机上用浏览器打开也应返回 JSON）
Invoke-RestMethod http://<电脑IP>:8000/api/health

# 当前 phone 快照
Invoke-RestMethod -Headers @{"X-Xiaoqi-Token"="<令牌>"} http://127.0.0.1:8000/api/state
```

## 5. 联调后端（dev_server）说明

- `GET /`：面板；`GET /api/state`；`GET /api/token`；`GET /api/health`；
- `POST /api/ingest/health`：与协议一致的 200/400/401、60s 幂等、只前进不回退；
- `GET /api/history`：默认近 7 天；
- `POST /api/reset`：需要 `X-Xiaoqi-Token`，清空演示数据；
- 数据默认落在 `build/demo-state.json`，重启保留；加 `--data <path>` 可换位置；
- 面板每 3 秒轮询 `/api/state`，不是 WebSocket；真实前端才走 WS。

如果想用真实后端但暂时没有摄像头，也可以只启动一个最小服务；本项目的
`tools/real-ingest-server.py` 就是这样做的（只装配真实 `PhoneIngest` 与 `/ws`，
用于测试，不是给日常使用的）。

---

## 6. 安全提醒

- 只在可信局域网使用；令牌等同于上报权限；
- 当前是明文 HTTP；不要在公网直接暴露 8000 端口；
- APK 是调试签名，不要用于正式分发；
- 深链 `xiaoqi://pair` 可被同机应用触发；高安全要求时改用扫码/一次性配对码；
- 令牌明文存应用私有目录，`allowBackup=false`；不要在截图/日志里泄露。
