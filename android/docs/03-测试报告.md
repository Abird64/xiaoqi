## 3. 测试方法

### 3.1 纯 Java 核心

`tools/test-core.ps1` 用 JDK 编译：

- `app/src/main/java/com/xiaoqi/steps/core/*.java`（不依赖 Android）；
- `app/src/test/java/com/xiaoqi/steps/core/CoreSelfTest.java`。

`CoreSelfTest` 自带一个 `com.sun.net.httpserver.HttpServer`，在随机端口模拟：
`/api/ingest/health`（200/400/401、`deduped`）、`/api/token`、`/api/health`、`/api/state`；
不访问外网。

### 3.2 独立联调后端

`tools/test-dev-server.py` 启动 `tools/dev_server.py` 子进程，用标准库
`urllib` 调用：

- 首次上报、同设备 60s 内重复、换设备、更小步数（跨天/重置）；
- `state` / `history` / `reset`；
- 400 字段校验、401 错误令牌；
- 面板 HTML 与「无数据不补 0」。

### 3.3 真实后端链路

`tools/test-integration.py`：

1. 用参考 venv 启动 `tools/real-ingest-server.py`；
2. 该脚本只读 `import` 真实 `xiaoqi.config.Config`、`xiaoqi.hub.Hub`、
   `xiaoqi.ingest.phone.PhoneIngest` 与 `build_router`，装配最小的 FastAPI + `/ws`；
3. 用 `SyncHarness`（与 App 同一份 `SyncClient`）发真实 POST；
4. 用 `websockets` 客户端连 `/ws`，断言收到 `hello` 与 `state.phone` 增量帧；
5. 断言真实 `PhoneIngest` 的令牌、60s 幂等、只前进不回退；
6. 通过测试专用 `/api/debug` 确认 `source=android-app` 与 `device_id` 真的进入后端。

这不是 mock 协议：HTTP 路由、响应体、幂等实现都来自参考后端源码。

### 3.4 APK 静态检查

`tools/build-apk.ps1` 走完整链路，并执行：

- `apksigner verify --verbose --print-certs`
- `aapt2 dump badging`
- `aapt2 dump xmltree --file AndroidManifest.xml`
- `dexdump -f`（解出 `classes.dex`）
- `Get-FileHash SHA256`

## 6. 未覆盖 / 风险

1. **真机运行未测**：本环境 `adb devices` 为空，SDK 无系统镜像，无法启动模拟器。
   以下必须在真机确认：
   - `TYPE_STEP_COUNTER` 是否可用、`ACTIVITY_RECOGNITION` 权限流程；
   - 前台服务 + 通知在各厂商 ROM 的存活；
   - Android 14 的 `health` 前台服务类型；
   - 锁屏/Doze 下的传感器批量上报与零点日切；
   - UI 在窄屏/大字体/深色模式下的布局；
   - 真机与后端同 Wi-Fi 的 HTTP 明文访问。
2. **真实后端全链路未跑**：测试环境没有完整安装后端姿态依赖（torch / LW 权重等），
   无法启动完整 `main.py` 的摄像头抽检链。但手机接入所依赖的 `PhoneIngest`、`Hub`、`/ws`
   已用真实源码验证；`main.py` 的 WS 路由与测试装配一致。
3. **首次安装从 0 开始**：不是 bug，是避免把“开机以来”步数虚报为今天的设计取舍。
4. **`screen_minutes` / `top_apps` 未实现**：D-009 的可选扩展；当前参考后端也未消费。
5. **调试签名 / 明文 HTTP**：仅课程演示；正式分发需正式 keystore 与 HTTPS。
6. **厂商后台策略**：JobScheduler / 前台服务不能保证 100% 存活；需要真机验证并引导白名单。

## 7. 真机验收建议

见 [`04-真机验收清单.md`](04-真机验收清单.md)。最小闭环：

1. 安装 APK，授予身体活动 + 通知；
2. 配置地址/令牌，保存并启动；
3. 走 100 步，点立即同步，后端 `/api/state` 的 `steps` 增加；
4. 打开小栖房间，步数卡/挂历更新；
5. 锁屏 10 分钟，再走 50 步，确认步数继续累计且能同步；
6. 跨零点观察今日归零（可用改系统时间/演示清零辅助）；
7. 重启手机，确认服务恢复；
8. 断开 Wi-Fi，确认显示同步失败且不崩溃；恢复后自动重试成功。
