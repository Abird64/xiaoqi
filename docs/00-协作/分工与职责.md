# 分工与职责

> 切分原则：**按可交付模块切，不按课程切**。（同一份产出往往同时服务两门课，按课程切必然重复劳动。）
> 每人有**一个主域 + 一个备份域**：主域内你是决策者，备份域内你是应急人。

---

## 一、三个主域

| | 成员 A | 成员 B | 成员 C |
|---|---|---|---|
| **主域** | 感知与后端 | 房间与前端 | 数据链路与交付 |
| **一句话** | 把「人的状态」变成数据 | 把「数据」变成一个能住的世界 | 把「外部数据」接进来，把「过程」交出去 |
| **主要产出** | 姿态判定 + 状态机 + 服务端 | 3D 房间 + 健康伙伴 + 可视化 | 行为/手机数据 + 联调测试 + 全部交付文档 |
| **关键路径** | ⚠️ 最长（M1 卡这儿） | ⚠️ 美术量最大 | 前期轻、后期重 |
| **备份域** | 成员 B 的联调接口部分 | 成员 A 的状态机部分 | 成员 A 的存储与提醒部分 |

> **姓名待填**：`成员 A = ______　成员 B = ______　成员 C = ______`

### 覆盖率校验

- 三人都有明确的 `W*` 归属，**没有"大家共同负责"的模块**（共同负责 = 没人负责）。
- 每个模块都有**备份人**和**评审人**，且都不是主责本人。

## 四、不相容职责（避免自己批自己）

- 写代码的人**不能**是自己代码的唯一评审人 → 每张卡的评审人必须填另一个人。
- 定接口的人（C）**不能**同时是唯一实现人 → W11 实现完必须由 A 或 B 实测一次。
- 报"做完了"的人**不是**验收人 → 里程碑验收由当周轮值主持执行。

## 五、负载失衡怎么办

三人节奏不可能一样，按下面顺序处理（**每周会检查一次**）：

1. **看板上谁的"进行中"≥ 3 张** → 把其中 `low` 优先级的卡退回待办。
2. **某人连续两周超载** → 把他的一个模块**整块**转给备份人（不是打散成碎片）。
3. **某人连续两周欠载** → 从 C 的交付物里分一块给他（文档类最容易拆）。
4. **临时掉线（生病 / 考试周）** → 只做一件事：**在看板把他的卡移到"阻塞"并写原因**，其他人不静默接手。

> ⚠️ 最危险的情况不是慢，而是"某人的模块只有他会"。所以每两周一次 **30 分钟交叉交接**：
> 主责讲 15 分钟（这块代码在哪、怎么跑、坑在哪），备份人复述 5 分钟，记录写进周报。
