## 规则

1. **一份文档只有一个主笔**。别人可以提意见、直接改错别字，但结构性修改要跟主笔说。
2. **事实性内容（数据、尺寸、接口字段）必须与代码一致**。代码改了文档没改 = bug。
3. **设计文档不写心路历程**。只写"是什么、为什么这么定、代价是什么"。
4. 需求一旦确认，改动走 [风险与决策](../01-规划/风险与决策.md) 的决策记录；**不许静默漂移**。
