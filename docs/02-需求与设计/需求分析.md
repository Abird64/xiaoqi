## 一句话需求

> 一款面向长期伏案、重度使用电脑的大学生和办公族的健康陪伴 App，通过集中获取并卡通化展示用户的坐姿、久坐时间、喝水次数、步数等实时数据，帮助用户了解并愿意主动调整自己的健康状态，辅助养成良好姿态与生活习惯。

## 02 问题与目标（Why——为什么做？）

### 2.1 目标用户

| 用户群体 | 特征 |
|---------|------|
| **大学生** | 长时间伏案学习、写论文、敲代码，久坐不动，坐姿随意，缺乏健康管理意识。 |
| **办公族** | 重度使用电脑，工作日均屏幕时间长，工作节奏快，容易忘记喝水、起身活动。 |

### 2.2 核心痛点

| 痛点 | 具体表现 |
|-----|---------|
| **坐姿不良** | 长期驼背、伏案，导致颈椎、腰椎问题，但用户自身往往察觉不到。 |
| **久坐不动** | 一坐就是几小时，缺乏起身活动意识，血液循环不畅。 |
| **忘记喝水** | 专注工作/学习时经常忘记喝水，身体长期处于缺水状态。 |
| **运动不足** | 日常步数偏低，缺乏活动量，但没有直观的数据反馈。 |
| **数据分散** | 坐姿、久坐、喝水、步数等健康数据分散在不同设备和应用中，无法集中查看。 |
| **提醒无感** | 传统弹窗式提醒容易被忽略甚至关闭，用户缺乏持续关注健康的动力。 |

### 2.3 价值目标

| 目标层级 | 内容 |
|---------|------|
| **功能目标** | 集中获取坐姿、久坐时间、喝水次数、步数等多源健康数据，实时展示。 |
| **体验目标** | 以低多边形 3D 卡通小房间 + 健康伙伴的形式（3D 优先，2.5D 为降级预案），将枯燥数据转化为生动的视觉反馈，让用户"愿意看"。 |
| **行为目标** | 通过角色状态变化和温和提醒，促使用户主动调整坐姿、起身活动、按时喝水。 |
| **长期目标** | 辅助用户养成良好的姿态与生活习惯，将健康管理融入日常工作学习场景。 |

### 2.4 从"感觉"到"目标"

| 用户原话 | 转化后的目标 |
|---------|------------|
| "坐久了腰和脖子都不舒服，但总是想不起来动一动。" | 久坐检测与定时提醒，帮助用户建立起身活动的节奏 |
| "知道自己坐姿不好，但没人提醒，改不过来。" | 实时姿态检测，通过视觉反馈让用户感知当前坐姿状态 |
| "一忙起来就忘了喝水，一天下来水杯还是满的。" | 喝水提醒机制，以角色互动代替生硬弹窗 |
| "每天走了多少步也没概念，健康数据散在各个 App 里。" | 多源数据集中展示，步数等信息一目了然 |
| "那些健康软件打开看一眼就关了，坚持不下来。" | 卡通化陪伴式呈现，让健康监测变得有趣、有情感连接 |

## 03 用户任务（What——用户要完成什么？）

### 3.1 用户任务拆解

用户使用「小栖」的完整任务链非常轻量——核心是"装好、摆好、然后正常生活"：

```
01 电脑端安装软件 → 02 手机侧配置上报（快捷指令 / HTTP Shortcuts）→ 03 两端配对连接
→ 04 摆放外置摄像头到合适位置 → 05 启动系统 → 06 正常使用电脑
→ 07 系统持续采集数据并实时展示 → 08 接收提醒并调整行为
```

### 3.2 任务详情

| 步骤 | 任务 | 说明 |
|-----|------|------|
| **01 电脑端安装** | 在 Windows 电脑上安装小栖桌面端 | 包含后端服务与前端展示页面，负责姿态检测、应用使用统计、提醒调度。 |
| **02 手机侧配置** | 在手机上用系统现成工具（iOS 快捷指令 / Android HTTP Shortcuts）配置定时上报 | 读取本机健康库的步数，POST 到电脑端的带令牌接口；**不开发手机 App**（D-002）。 |
| **03 两端连接** | 完成电脑端与手机端的配对连接 | 手机数据通过网络同步至电脑端系统，实现多源数据汇聚。 |
| **04 摆放摄像头** | 将外置 USB 摄像头摆放到能正确捕捉人体姿态的位置 | 摄像头需对准用户上半身，确保姿态检测的准确性。启动时可引导用户"坐直"完成校准。 |
| **05 启动系统** | 打开小栖，进入 3D 房间界面（3D 优先） | 健康伙伴出现在房间中，开始实时反映用户状态。 |
| **06 正常使用** | 用户正常工作、学习，无需额外操作 | 系统在后台静默运行，持续采集坐姿、久坐、应用使用等数据。 |
| **07 实时展示** | 房间中的健康伙伴随用户状态变化 | 坐姿端正时伙伴精神，驼背时伙伴弯腰，久坐时伙伴提醒起身——数据被"翻译"成角色行为。 |
| **08 接收提醒并调整** | 用户根据角色反馈和提醒调整行为 | 如收到久坐提醒后起身活动，收到驼背提醒后调整坐姿。 |

> **核心特点：用户任务到此为止。** 安装、连接、摆放摄像头之后，用户不需要再做任何主动操作——系统自动采集、自动展示、自动提醒。用户的"任务"就是正常生活，而系统在背后陪伴。

### 3.3 User Story

```
As a 长期伏案的大学生/办公族
I want to 在我日常使用电脑时，有一个卡通伙伴实时反映我的坐姿、久坐、喝水和运动状态
So that 我能直观地了解自己的健康状况，并愿意主动调整不良习惯
```

## 04 业务流程（How——现实业务怎样运行？）

### 4.1 主业务流程

小栖的业务流程核心是**"多源输入 → 状态计算 → 视觉展示 → 行为提醒"**的闭环：

```
┌─────────────────────────────────────────────────────────────┐
│                        用户端（多信源输入）                    │
│                                                             │
│  外置摄像头 ──→ 坐姿/姿态数据                                 │
│  电脑端     ──→ 久坐时长 / 前台应用使用时长                    │
│  手机端     ──→ 步数 / 静止状态                               │
│  用户交互   ──→ 喝水记录（手动确认或行为推断）                  │
└──────────────────────────┬──────────────────────────────────┘
                           │ 数据汇聚
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                      系统核心（计算与调度）                    │
│                                                             │
│  姿态判定 → 状态机 → 提醒调度 → 数据聚合                      │
└──────────────────────────┬──────────────────────────────────┘
                           │ 状态输出
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                      呈现层（3D 房间，3D 优先）                       │
│                                                             │
│  健康伙伴状态切换 → 房间环境变化 → 信息可视化 → 温和提醒        │
└──────────────────────────┬──────────────────────────────────┘
                           │ 反馈
                           ▼
                    用户感知并调整行为
                           │
                           └──────→ 行为变化重新被采集（闭环）
```

### 4.2 流程步骤说明

| 步骤 | 说明 |
|-----|------|
| **01 多源数据采集** | 摄像头实时采集坐姿关键点；电脑端统计前台应用与久坐时长；手机端同步步数数据。 |
| **02 数据汇聚与计算** | 后端接收各信源数据，进行姿态判定、时长累计、步数统计等处理。 |
| **03 状态机驱动** | 根据计算结果切换系统状态（正常 / 驼背 / 久坐 / 喝水提醒等），驱动健康伙伴行为。 |
| **04 实时展示** | 前端 3D 房间中，健康伙伴和环境随状态变化，数据以卡通化方式呈现。 |
| **05 提醒触发** | 当满足提醒条件（如久坐超过阈值、长时间未喝水）时，以角色行动/表情触发温和提醒。 |
| **06 用户响应** | 用户看到伙伴状态变化或提醒后，调整坐姿、起身活动或喝水。 |
| **07 闭环反馈** | 用户行为调整后，新的姿态/活动数据重新被采集，状态随之恢复正常，形成闭环。 |

### 4.3 分支场景

| 分支场景 | YES 处理 | NO 处理 |
|---------|---------|---------|
| **坐姿是否正常？** | 健康伙伴保持正常状态，房间环境明亮积极。 | 判定为驼背/伏案并持续 N 秒后，伙伴做出弯腰/疲惫表现，温和提示调整坐姿。 |
| **久坐是否超时？** | 触发久坐提醒，伙伴表现出想活动的样子，房间出现动态提示。 | 状态正常，伙伴保持当前状态。 |
| **是否到喝水时间？** | 伙伴做出喝水/递水杯的动作，提醒用户喝水。 | 不触发提醒。 |
| **摄像头是否捕捉到人？** | 正常进行姿态检测。 | 用户离开座位，暂停姿态检测，伙伴进入"等待"状态；离开时间计入久坐/起身统计。 |
| **手机端是否已连接？** | 步数数据实时同步，房间中展示当日步数。 | 步数模块显示"未连接"，其余功能正常运行。 |

### 4.4 异常场景

| 异常场景 | 处理方式 |
|---------|---------|
| **摄像头被遮挡/未连接** | 前端提示摄像头异常，姿态检测暂停，不影响其他功能。 |
| **手机端断连** | 步数数据暂停更新，显示最后同步时间，恢复后自动续传。 |
| **姿态误判** | 启动时引导用户校准基准姿势；设置持续 N 秒的防抖阈值，减少瞬时误报。 |
| **用户关闭提醒** | 允许用户自定义提醒频率和静默时段，但保留伙伴的视觉状态变化。 |

## 05 系统功能（System——系统要提供什么能力？）

### 5.1 功能总览

| 编号 | 功能 | 优先级 | 说明 |
|-----|------|-------|------|
| **F01** | 驼背检测 | P0 | 通过外置摄像头实时估计人体关键点，判定坐姿状态（坐直 / 驼背 / 伏案），驱动健康伙伴行为变化。 |
| **F02** | 久坐提醒 | P0 | 统计连续坐姿时长，超过阈值后以角色行动/表情提醒用户起身活动。 |
| **F03** | 喝水提醒 | P1 | 按时间间隔或用户设定提醒喝水，以角色互动代替生硬弹窗。 |
| **F04** | 手机端步数 | P1 | 手机采集步数数据，同步至电脑端，在房间中可视化展示当日运动量。 |
| **F05** | 应用使用时长 | P1 | 统计 Windows 前台应用焦点与使用时长，在房间中以可视化方式回应用户的电脑使用行为。 |

### 5.2 功能详情

#### F01 驼背检测

| 项目 | 内容 |
|-----|------|
| **输入源** | 外置 USB 摄像头 |
| **核心逻辑** | 实时估计人体关键点（头、肩、躯干等），以头前倾角等几何量判定姿态；超过阈值并持续 N 秒 → 切换为"驼背"状态。 |
| **校准机制** | 首次启动引导用户"坐直"，采集个性化基准阈值。 |
| **输出** | 姿态状态（坐直 / 驼背 / 伏案 / 起身 / 无人）→ 驱动健康伙伴动画切换。 |

#### F02 久坐提醒

| 项目 | 内容 |
|-----|------|
| **输入源** | 摄像头（检测是否在位）+ 系统时间 |
| **核心逻辑** | 连续检测到用户处于坐姿且未起身超过设定时长（如 45 分钟），触发久坐提醒。 |
| **提醒方式** | 健康伙伴表现出疲惫/想活动的状态，房间环境出现视觉提示，而非弹窗打断。 |
| **重置条件** | 用户起身离开座位超过一定时间后，久坐计时重置。 |

#### F03 喝水提醒

| 项目 | 内容 |
|-----|------|
| **输入源** | 系统时间 + 用户手动确认 |
| **核心逻辑** | 按设定间隔（如 60 分钟）触发喝水提醒；用户可标记"已喝水"重置计时。 |
| **提醒方式** | 健康伙伴做出喝水/递水杯动作，房间中出现水杯相关视觉元素。 |
| **记录** | 记录当日喝水次数，在房间中可视化展示。 |

#### F04 手机端步数

| 项目 | 内容 |
|-----|------|
| **输入源** | 手机端传感器（加速度计等） |
| **核心逻辑** | 手机侧自动化工具（快捷指令 / HTTP Shortcuts）读取本机健康库当日步数，经带令牌的 HTTP 上报至电脑端；电脑端幂等去重后落库。 |
| **展示方式** | 在 3D 房间中以卡通化元素展示当日步数（如伙伴的活动量、房间中的步数标识）。 |
| **连接状态** | 未连接时显示"待同步"，连接后实时更新。 |

#### F05 应用使用时长

| 项目 | 内容 |
|-----|------|
| **输入源** | Windows 前台应用焦点（pywin32 / psutil） |
| **核心逻辑** | 统计当前前台应用名称与持续使用时长，本地轻量记录，不上传隐私数据。 |
| **展示方式** | 在房间中以可视化方式回应用户正在使用的应用类型（如学习/工作/娱乐时，伙伴有不同表现）。 |
| **隐私保护** | 仅记录应用名称和时长，不记录内容；数据仅存本地。 |

### 5.3 需求五要素映射

| 要素 | 说明 |
|-----|------|
| **Who · 执行者** | 长期伏案、重度使用电脑的大学生和办公族。 |
| **When · 触发条件** | 用户安装并启动系统后，在日常使用电脑的全过程中持续运行。 |
| **What · 核心动作** | 用户无需主动操作；系统自动采集多源健康数据并卡通化展示。 |
| **Rule · 校验规则** | 姿态阈值判定、久坐时长阈值、喝水提醒间隔、步数同步频率、应用使用统计规则。 |
| **Result · 执行结果** | 3D 房间中健康伙伴实时反映用户健康状态，触发温和提醒，促使用户主动调整行为。 |
