## 一、分层与数据流

```
┌──────────────────────────────────────────────────────────────┐
│  呈现层（成员 A）                                              │
│  Three.js 房间世界 + 健康伙伴 + 房间内信息可视化                │
│  消费：WebSocket 状态消息（只读，不反向控制）                    │
└──────────────────────────▲───────────────────────────────────┘
                           │ WebSocket /ws（≤1 条/秒）
┌──────────────────────────┴───────────────────────────────────┐
│  计算层（成员 C）                                              │
│  FastAPI + WebSocket Hub                                      │
│  ├ 姿态判定与校准（MediaPipe 关键点 → 头前倾角 → 状态）          │
│  ├ 状态机（防抖 / 持续时长 / 迁移规则）                          │
│  ├ 提醒调度（喝水 / 久坐）                                      │
│  └ SQLite 持久化（姿态历史、行为时长、步数）                     │
└───────▲──────────────▲──────────────────────▲────────────────┘
        │              │                      │
   ┌────┴────┐   ┌─────┴──────┐        ┌──────┴───────────┐
   │ 摄像头   │   │ Windows    │        │ 手机（成员 D）    │
   │ 姿态     │   │ 前台应用    │        │ POST /api/ingest │
   │ (C)     │   │ (D)        │        │ /health (D)      │
   └─────────┘   └────────────┘        └──────────────────┘
```

### 三条数据链路（各自独立，互不阻塞）

| 链路 | 路径 | 主责 | 断了会怎样 |
|---|---|---|---|
| **姿态链**（核心） | 摄像头 → 关键点 → 判定 → 状态机 → WS → 房间 | C → A | 房间失去主要输入，只剩环境动 |
| **行为链** | Windows 前台应用 → 时长统计 → WS → 房间氛围 | D → C → A | 房间不反映电脑使用状态 |
| **手机链** | 快捷指令 → HTTP → 幂等去重 → 聚合 → WS → 可视化 | D → C → A | 步数相关展示为"无数据" |

> **设计原则**：任何一条链路挂掉，其余两条必须照常工作（`capabilities` 字段用于告知前端哪些链路当前可用）。

## 三、代码目录结构（**已定稿 · D-007**，2026-09-22，A 提议）

```
xiaoqi/
├── backend/
│   ├── pyproject.toml
│   ├── xiaoqi/
│   │   ├── __init__.py
│   │   ├── main.py          # FastAPI 入口 + WS Hub + 托管前端构建产物
│   │   ├── config.py        # 阈值 / 端口 / 令牌（YAML，改配置不改代码 → M2-2）
│   │   ├── hub.py           # 事件总线：各采集线程 → asyncio.Queue → 广播 + 落库
│   │   ├── vision/          # camera.py（采集线程）+ pose_estimator.py
│   │   ├── rules/           # posture_rules.py + calibration.py（校准）
│   │   ├── state/           # machine.py（防抖 / 持续时长 / 迁移）
│   │   ├── ingest/          # phone.py（令牌 + 幂等）+ behavior.py（前台应用线程）
│   │   └── store/           # db.py（SQLite schema）+ history 查询
│   ├── scripts/mock_server.py  # 按协议推假状态序列，解锁前端并行开发
│   ├── requirements.txt
│   └── tests/
├── frontend/                # Vite + Three.js（成员 A）
│   ├── src/                 # 场景 / 伙伴 / 可视化
│   └── public/assets/       # 低多边形模型与贴图
├── tools/                   # 成员 D：快捷指令模板；成员 B：误报统计、录制脚本
├── docs/                    # 本目录（四人共同）
└── README.md
```

### 进程模型（**单进程**，已定 · D-007）

| 执行体 | 职责 | 产出 |
|---|---|---|
| `vision` 采集线程 | 抓帧 + MediaPipe 推理（**绝不碰事件循环**） | `PoseEvent` |
| `ingest/behavior` 线程 | 轮询 Windows 前台应用 | `BehaviorEvent` |
| FastAPI 协程 | WS 广播 + HTTP 接入 + 落库 | — |

三路采集各自为独立线程，结果一律投 `asyncio.Queue`（`loop.call_soon_threadsafe`），由 Hub 统一广播 + 写 SQLite。
**理由**：M4-5 要求「干净机器一条命令跑起来」，单进程单端口是演示与交付的最短路径；多进程对这个体量只增加故障点。

### 交付形态（已定 · D-007）

- **开发**：Vite dev server + proxy 转发 `/ws`、`/api` → 免 CORS，各人热更新。
- **交付**：`npm run build` → 产物由 FastAPI `StaticFiles` 托管，**一条命令起全部：`python -m xiaoqi`**（单端口 8000，含前端页面）。

> 目录一旦定下来，**不要中途重塑**（会打断所有人的分支）。要改走决策记录。

## 四、关键运行约束

| 项 | 约束 |
|---|---|
| 平台 | Windows 为主 + 外置 USB 摄像头 |
| GPU | **不依赖**（MediaPipe CPU 可跑）——不能假设演示机器有独显 |
| 网络 | 后端与手机需同一 Wi-Fi；只监听局域网，不暴露公网 |
| 隐私 | 摄像头画面**不上传、不留存**；只留关键点数值与状态 |
| 性能底线 | 前端 ≥ 30 FPS（1080p）、内存不持续增长 |
| 降级 | W10 未达标 → 前端切 2.5D（见 [技术文档首页](../README.md) 第三节「里程碑与验收标准」） |
