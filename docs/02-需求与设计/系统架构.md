## 一、分层与数据流

```
┌──────────────────────────────────────────────────────────────┐
│  呈现层（成员 B）                                              │
│  Three.js 房间世界 + 健康伙伴 + 房间内信息可视化                │
│  消费：WebSocket 状态消息（只读，不反向控制）                    │
└──────────────────────────▲───────────────────────────────────┘
                           │ WebSocket /ws（≤1 条/秒）
┌──────────────────────────┴───────────────────────────────────┐
│  计算层（成员 A）                                              │
│  FastAPI + WebSocket Hub                                      │
│  ├ 姿态判定与校准（MediaPipe 关键点 → 头前倾角 → 状态）          │
│  ├ 状态机（防抖 / 持续时长 / 迁移规则）                          │
│  ├ 提醒调度（喝水 / 久坐）                                      │
│  └ SQLite 持久化（姿态历史、行为时长、步数）                     │
└───────▲──────────────▲──────────────────────▲────────────────┘
        │              │                      │
   ┌────┴────┐   ┌─────┴──────┐        ┌──────┴───────────┐
   │ 摄像头   │   │ Windows    │        │ 手机（成员 C）    │
   │ 姿态     │   │ 前台应用    │        │ POST /api/ingest │
   │ (A)     │   │ (C)        │        │ /health (C)      │
   └─────────┘   └────────────┘        └──────────────────┘
```

### 三条数据链路（各自独立，互不阻塞）

| 链路 | 路径 | 主责 | 断了会怎样 |
|---|---|---|---|
| **姿态链**（核心） | 摄像头 → 关键点 → 判定 → 状态机 → WS → 房间 | A → B | 房间失去主要输入，只剩环境动 |
| **行为链** | Windows 前台应用 → 时长统计 → WS → 房间氛围 | C → A → B | 房间不反映电脑使用状态 |
| **手机链** | 快捷指令 → HTTP → 幂等去重 → 聚合 → WS → 可视化 | C → A → B | 步数相关展示为"无数据" |

> **设计原则**：任何一条链路挂掉，其余两条必须照常工作（`capabilities` 字段用于告知前端哪些链路当前可用）。

## 四、关键运行约束

| 项 | 约束 |
|---|---|
| 平台 | Windows 为主 + 外置 USB 摄像头 |
| GPU | **不依赖**（MediaPipe CPU 可跑）——不能假设演示机器有独显 |
| 网络 | 后端与手机需同一 Wi-Fi；只监听局域网，不暴露公网 |
| 隐私 | 摄像头画面**不上传、不留存**；只留关键点数值与状态 |
| 性能底线 | 前端 ≥ 30 FPS（1080p）、内存不持续增长 |
| 降级 | W10 未达标 → 前端切 2.5D（见 [里程碑与验收标准](../01-规划/里程碑与验收标准.md)） |
