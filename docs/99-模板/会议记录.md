# 会议记录模板

> 复制为 `docs/03-进度/会议记录/YYYY-MM-DD-主题.md`，会后 **24 小时内**写完（轮值主持负责）。
> **只记三样：结论、谁做什么、什么时候。**过程讨论不用记。

---

```markdown
# 2026-MM-DD 周会

**在场**：A / B / C（缺席：）
**主持**：〈轮值主持〉
**时长**：30 min

## 一、看板过审

| 卡号 | 变更 | 说明 |
|---|---|---|
| XQ-0xx | ⬜ → ✅ | 证据：PR #? |
| XQ-0xx | 🔵 → 🔴 | 阻塞原因： |

## 二、结论（决定了什么）

1. 〈决定 1〉—— 影响范围：〈谁要跟着改〉
2. 〈决定 2〉

> 涉及接口 / 功能取舍 / 技术栈的结论，**必须**另外写进
> [01-规划/风险与决策.md](../01-规划/风险与决策.md) 的决策记录。

## 三、行动项

| 谁 | 做什么 | 期限 | 卡号 |
|---|---|---|---|
| A | | MM/DD | XQ-0xx |

## 四、下次会议

- 时间：2026-MM-DD 20:00
- 主持：〈下一位轮值〉
- 必须带：〈谁要准备什么，例如"B 演示角色动画"〉
```

---

## 周会固定三问（照顺序，不许跑题）

1. 看板上哪些卡动了？
2. 哪些卡卡住了？需要谁帮？
3. 下周各自领哪几张卡？

> 技术方案讨论**不在周会里**，另约 15 分钟或写成决策记录异步评审。

## 教师反馈记录（重要）

课堂/答疑里问到老师的口头意见，当天记在本文件末尾：

```markdown
## 教师反馈（2026-MM-DD，〈课程〉）

- 原话要点：〈尽量逐字，不要转述成你想要的意思〉
- 我们的理解：〈一句话〉
- 影响：〈要不要改设计 / 改哪张卡〉
```

> ⚠️ 口头反馈不记录 → 一周后三人会有三种说法。**这是多课程项目最容易失控的地方。**
