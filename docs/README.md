## 二、Git 纪律（三条，违反会打断别人）

1. **不许直接 push `main`** —— 走分支 → PR，**至少 1 人 approval**（写代码的人不能自评）。
2. **同一文件同一时间只允许一个人改** —— 要动别人的文件，先在群里说一句。
3. **接口字段只增不改** —— 废弃字段标 `deprecated`，不删名、不改名，版本号 +1，变更写进 `接口协议.md` 变更记录。

## 三、里程碑与验收标准（**跑给验收人看**，不看文档不听口述）

验收人 = 另一名成员，**不可是该里程碑主要实现者本人**。每条只有「做到 / 没做到」。

### M1 · 工具导通（W6 截止，约 10/11）—— 先不做动画补间、不做美术

| # | 验收标准 |
|---|---|
| M1-1 | 摄像头能在目标机器上稳定取帧 ≥ 5 分钟不崩 |
| M1-2 | 能实时输出人体关键点，并在画面上标出（调试模式） |
| M1-3 | 能算出至少 1 个姿态指标（头前倾角）并打印数值 |
| M1-4 | 服务端能通过 WebSocket 把状态推给前端，前端显示当前状态文字 |
| M1-5 | 做「坐直 → 驼背」动作，**3 秒内**前端状态跟着变 |
| M1-6 | 拔掉摄像头 / 杀掉服务端，程序不出现不可恢复崩溃 |

### M2 · 判定调校（W8 截止，约 10/25）—— 人机课报告的核心素材

| # | 验收标准 |
|---|---|
| M2-1 | 有个人化校准流程（启动时按提示「坐直」采样基准） |
| M2-2 | 阈值参数可配置，**不用改代码**就能调 |
| M2-3 | 实测 ≥ 30 分钟连续记录，产出误报/漏报统计表 |
| M2-4 | 误报率与漏报率对比调校前有明显改善（给出两组数） |
| M2-5 | 状态切换有防抖（不是一闪一闪） |
| M2-6 | 数据留存可供报告使用（CSV 或截图） |

### M3 · 呈现层（W12 截止，约 11/22）—— 多媒体课的核心

| # | 验收标准 |
|---|---|
| M3-1 | 低多边形房间场景完整（墙角 + 桌椅 + 电脑），有整体光照 |
| M3-2 | 健康伙伴角色在场景中，**至少 4 个姿态状态**有不同表现 |
| M3-3 | 状态切换有过渡补间，不生硬跳变 |
| M3-4 | 行为数据（前台应用/时长）在房间中有可视化回应 |
| M3-5 | 手机步数能通过局域网进入系统并可视化（用真手机现场跑） |
| M3-6 | 连续运行 ≥ 30 分钟，帧率稳定不卡死、不掉内存 |
| M3-7 | 桌面分辨率下展示效果达标（不达标则触发 2.5D 降级决策） |

### M4 · 打磨与交付（W15 截止，约 12/13）

| # | 验收标准 |
|---|---|

### 降级触发器（不是失败，是预案）

| 触发条件 | 降级动作 | 谁决定 |
|---|---|---|
| W10 结束时房间 3D 仍卡顿/美术不达标 | 前端切 **2.5D 等距精灵 + 视差**（状态驱动内核不变） | 全员，记 ADR |
| W10 结束时姿态误报率仍不可接受 | 收窄到 2 个状态（坐直 / 非坐直） | 全员，记 ADR |
| W11 结束时手机端仍跑不通 | 改为手动录入步数（接口不动） | D 提议 + C 确认 |
| 某成员 W9 之前累计掉线 ≥ 1 周 | 触发分工重排 | 全员 |
