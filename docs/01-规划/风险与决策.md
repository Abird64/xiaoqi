## 二、决策记录（ADR）

**什么时候要写**：影响范围、功能取舍、技术栈变更、接口冻结。**写完就不再反复讨论**，除非有新证据。

### 模板

```markdown
### D-00x 决策标题（YYYY-MM-DD）
- **背景**：为什么要做这个决定
- **选项**：A / B / C 各自代价
- **决定**：选了哪个
- **理由**：一句话
- **影响**：谁要跟着改什么
- **可逆性**：可逆 / 不可逆（不可逆的要三人一致同意）
- **参与人**：谁在场
```

---

### D-001 前端采用 Three.js 3D 路线，2.5D 作为降级预案（2026-09-06）

- **背景**：房间世界是多媒体课的核心卖点，但 3D 美术与性能都有风险。
- **选项**：A 纯 2.5D 等距精灵（稳但作品感弱）｜B Three.js 3D（上限高、风险高）｜C 先 2.5D 再升级
- **决定**：**B，并保留 A 作为降级预案**。
- **理由**：作品感是这门课的核心评分点；降级预案保证最坏情况仍可交付。
- **影响**：前端工作量集中在 B 身上；W10 设降级触发器（见里程碑文件）。
- **可逆性**：可逆（状态驱动内核不变，换渲染层不影响后端）。
- **参与人**：三人 + 教师方向确认。

### D-002 手机端数据「协议优先，客户端零开发」（2026-09-14）

- **背景**：老师建议加入手机数据（步数/静止），但自研 App 工期不够。
- **选项**：A 自研 App 对接 HealthKit / Health Connect｜B 系统现成工具（快捷指令 / HTTP Shortcuts）+ 后端暴露带令牌接口｜C 不做手机端
- **决定**：**B**。电脑端提供 `POST /api/ingest/health`，手机侧零代码接入。
- **理由**：手机只作为一路**数据源**，不是客户端；省掉开发、审核、上架。
- **影响**：后端要承担令牌校验与幂等去重；前端只消费聚合后的步数。
- **可逆性**：可逆（接口不变，换数据来源而已）。
- **参与人**：三人。

### D-003 团队协作以仓库 `docs/` 为唯一真相源（2026-09-16）

- **背景**：3 人只有 1 人维护个人知识库，队友看不到；口头约定容易漂移。
- **选项**：A 微信群 + 口头｜B 第三方协作工具（飞书/Notion）｜C 仓库内 `docs/` 文件
- **决定**：**C**，并按「协作 / 规划 / 需求设计 / 进度 / 交付物」分层。
- **理由**：跟代码同仓、可 diff、可离线、无需额外账号；任务状态只有一个看板文件。
- **影响**：文档变更也走 PR；看板是唯一的任务真相源。
- **可逆性**：可逆。
- **参与人**：三人。
