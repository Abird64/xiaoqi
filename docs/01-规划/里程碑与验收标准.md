# 里程碑与验收标准

> 验收规则：**跑给验收人看**，不看文档、不听口述。每条标准只有"做到 / 没做到"两种结果。
> 验收人 = 当周轮值主持（不可是该里程碑主要实现者本人）。

---

## M1 · 工具导通（W6 截止，约 10/11）

**目标**：一条完整链路跑起来，先不做动画补间、不做美术。

| # | 验收标准 | 验证方式 |
|---|---|---|
| M1-1 | 摄像头能在目标机器上打开并稳定取帧 ≥ 5 分钟不崩 | 现场跑 |
| M1-2 | 能实时输出人体关键点，并在画面上标出（调试模式） | 现场跑 |
| M1-3 | 能算出至少 1 个姿态指标（头前倾角）并打印数值 | 现场跑 |
| M1-4 | 服务端能通过 WebSocket 把状态推给前端，前端显示当前状态文字 | 两个终端现场跑 |
| M1-5 | 做「坐直 → 驼背」动作，3 秒内前端状态跟着变 | 现场跑 |
| M1-6 | 拔掉摄像头/杀掉服务端，程序不出现不可恢复崩溃 | 现场跑 |

## M2 · 判定调校（W8 截止，约 10/25）

**目标**：阈值可用，有数据说话（这是人机课报告的核心素材）。

| # | 验收标准 | 验证方式 |
|---|---|---|
| M2-1 | 有个人化校准流程（启动时按提示"坐直"采样基准） | 现场跑 |
| M2-2 | 阈值参数可配置，不用改代码就能调 | 改配置跑 |
| M2-3 | 实测 ≥ 30 分钟的连续记录，产出误报/漏报统计表 | 看数据表 |
| M2-4 | 误报率与漏报率有明显改善（对比调校前，给出两组数） | 看数据表 |
| M2-5 | 状态切换有防抖（不是一闪一闪） | 现场跑 |
| M2-6 | 数据留存可供人机课报告使用（CSV 或截图） | 看文件 |

---

## M3 · 呈现层（W12 截止，约 11/22）

**目标**：从"能用"变成"值得看"（这是多媒体课的核心）。

| # | 验收标准 | 验证方式 |
|---|---|---|
| M3-1 | 低多边形房间场景完整（墙角 + 桌椅 + 电脑），有整体光照 | 现场看 |
| M3-2 | 健康伙伴角色在场景中，至少 4 个姿态状态有不同表现 | 现场看 |
| M3-3 | 状态切换有过渡补间，不生硬跳变 | 现场看 |
| M3-4 | 行为数据（前台应用/时长）在房间中有可视化回应 | 现场跑 |
| M3-5 | 手机步数能通过局域网进入系统并可视化 | 现场跑（用真手机） |
| M3-6 | 连续运行 ≥ 30 分钟，帧率稳定不卡死、不掉内存 | 现场跑 |
| M3-7 | 桌面分辨率下展示效果达标（3D 不达标则触发 2.5D 降级决策） | 现场看 |

## 降级决策触发器（不是失败，是预案）

| 触发条件 | 降级动作 | 谁决定 |
|---|---|---|
| W10 结束时房间 3D 仍卡顿/美术不达标 | 前端切 **2.5D 等距精灵 + 视差**（状态驱动内核不变） | 全员，记决策记录 |
| W10 结束时姿态误报率仍不可接受 | 收窄到 2 个状态（坐直 / 非坐直），放弃细分状态 | 全员，记决策记录 |
| W11 结束时手机端仍跑不通 | 改为手动录入步数（保留接口不动） | C 提议 + A 确认 |
| 某成员 W9 之前累计掉线 ≥ 1 周 | 触发 [分工与职责](../00-协作/分工与职责.md) 第五节的分工重排 | 全员 |
