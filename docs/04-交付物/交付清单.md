## 二、存放规则

| 类型 | 放哪 | 规则 |
|---|---|---|
| 文字类（报告/说明书） | `docs/02-需求与设计/` 或 `docs/04-交付物/` | **只存 Markdown**，导出 PDF 时同时提交 PDF |
| PPT / 视频 / 大文件 | 外部网盘（留链接在本表） | 超过 5 MB **不进仓库** |
| 讲课现场用的图片 | `docs/04-交付物/assets/` | 单张 < 1 MB |

> 命名统一：`<课程简称>-<交付物>-<版本>.md`，例：`多媒体-作品报告-v1.md`。
> 课程简称：**人机课** = 人机交互（HCI）｜**实训课** = 数字媒体中级实训｜**多媒体** = 多媒体技术实训。

## 三、写作纪律（避免最后一周通宵）

1. **边做边存证据**：每次实测、每次联调，截图 + 一句话结论丢进当天会议记录或周报。写报告时只是**组装**，不是回忆。
2. **数据和代码必须一致**：报告里写的阈值、误报率必须能从代码/数据文件复现。
3. **一份素材服务多门课**：同一份测试数据，人机课讲"可用性"，多媒课程讲"作品体验"，**不要重新测一遍**。
4. **教师反馈当天记录**：问老师得到的口头意见，24 小时内写进 [风险与决策](../01-规划/风险与决策.md)，否则一周后就变成三种说法。
5. **每份交付物必须有评审人**：主笔写完 → 至少 1 人通读 → 才能算 ✅。
